# 蜀韵·智游 · 答辩问答（20 问）

> 每题答案按 80–150 字口播稿拟写，可直接背。

---

## 一、项目定位类（4）

**Q1：你们的项目是做什么的？一句话介绍。**
蜀韵·智游是一个面向四川旅游的"文化 + AI"一站式平台：游客能查景点、美食、文化与非遗，还能用 AI 管家生成个性化行程；管理端与数据大屏则支撑内容运营与实时决策。

**Q2：为什么选"四川文旅"这个方向？**
四川文旅资源极丰富但信息分散：景点、美食、川剧、蜀绣、非遗传承人散落各处，游客查一次攻略要开很多 App。我们把 350 条川蜀真实数据整合进一个平台，并用 AI 把"查资料"升级为"给方案"。

**Q3：目标用户和核心价值是什么？**
面向自由行游客与文化爱好者。核心价值有二：一是"一站式 + 有文化深度"的内容聚合；二是"主动 + 个性化"的 AI 服务——不等你来问，而是主动推送天气客流、主动生成行程。

**Q4：和携程、马蜂窝这类产品比，你们的差异点？**
我们不做大而全，而是把"文化"做深：非遗传承人、文化脉络、蜀锦纹样视觉体系都是特色。再加上女娲智能体驱动的 AI 行程管家与 3D 数据大屏，形成"内容 + 智能 + 可视化"的差异化。

## 二、技术实现类（6）

**Q5：整体技术架构是怎样的？**
后端是 Spring Boot 3 多模块（common/pojo/mapper/service/ai/web/admin），MyBatis-Plus + MySQL + Redis；前端是 Vue3 + Vite + TypeScript + Element Plus。前端按"前台 / 用户后台 / 管理后台"三套路由分流，共用一套设计令牌与组件库。

**Q6：AI 对话是怎么实现的？**
后端 `shuyun-ai` 用 Spring WebFlux 的 `WebClient` 流式请求女娲智能体平台，把 SSE 分片原样透传给前端；前端用 `fetch` 读 `ReadableStream` 增量解析，逐字渲染到气泡，并兼容 Markdown、支持重试降级。

**Q7：首页那种"整屏滚动"的动画怎么做？**
用 Lenis 接管滚动并接入 GSAP ScrollTrigger（scrollerProxy 桥接），分节吸附 + 交叉淡入；所有动画走一个 rAF 循环，并用 `will-change: transform` 提升合成层，保证 60fps。

**Q8：数据大屏的实时性怎么保证？**
前端建立 WebSocket 长连接监听 `/ws/screen`，后端定时任务/事件触发推送增量数据；前端收到后直接 `setOption` 更新 ECharts 与 KPI，无刷新、无轮询，断线自动重连。

**Q9：前端如何保证视觉一致性？**
我们建了三层规范：SCSS 设计令牌（颜色/字号/间距/阴影）、mixin（hover-lift、responsive、glass 等）、公共组件（StateBlock、Pagination、GoldButton）。页面只组合令牌与组件，不各写各的。

**Q10：全站的加载/空/错误状态怎么统一？**
抽了一个 `StateBlock.vue`：`state` 传 loading/empty/error，分别渲染金色骨架屏、蜀锦纹样空态、金色警示 + 重试按钮。前台列表、详情与首页分节全部接入，视觉与交互完全一致。

## 三、数据来源类（4）

**Q11：数据从哪来？有多少？**
从公开渠道整理成 4 个 Excel：景点 100、美食 100、文化 50、非遗 100，共 350 条真实数据；图片按分类归档在 `shuyun-data/images` 下。

**Q12：怎么把 Excel 变成数据库数据的？**
写了 `tools/excel2sql.py`（pandas + openpyxl）：读表 → 类型推断 → 空值转 NULL → 单引号转义 → 图片路径重写 → 图片拆子表 → 生成幂等 SQL。一行命令产出 `data.sql`，可直接导入。

**Q13：数据导入怎么保证不覆盖已有数据？**
SQL 用 `CREATE TABLE IF NOT EXISTS` + `INSERT ... ON DUPLICATE KEY UPDATE`，即"存在则更新、不存在则插入"的 upsert；`city_id` 用 `(SELECT id FROM city WHERE name=…)` 动态匹配，避免写死主键。

**Q14：非遗数据没有封面图，你们怎么处理？**
非遗表确实没有图片字段。我们设计了"首字色卡"方案：用墨蓝渐变底 + 大号名称首字 + 蜀锦纹理生成卡片主视觉，既统一美观又保留辨识度，无需再补图。

## 四、差异化亮点类（6）

**Q15：你们说的"主动式关怀"具体指什么？**
传统产品等你搜索。我们后端用定时任务聚合天气与客流数据，通过 WebSocket 主动推给前端；用户在详情页、大屏无需操作就能看到"今日客流较高""有降雨提醒"等关怀信息。

**Q16：3D 地图和飞线是怎么做的？**
用 `echarts-gl`：`map3D` 渲染四川 GeoJSON 三维地图，`lines3D` 画跨城飞线，并用流动 `effect` 做动画；景点经纬度点位叠加成散点，数据由 WebSocket 实时驱动更新。

**Q17：个人中心的侧边栏有什么讲究？**
可折叠（240px↔64px），折叠状态写入 localStorage 记忆；折叠后只显示线性图标、hover 出 tooltip；选中项为蜀锦红底 + 金色左竖条；小屏自动变抽屉，兼顾桌面与移动端。

**Q18：全站视觉是怎么做到"高级感"的？**
一套"蜀锦红 + 金沙金 + 宣纸米 + 青城墨蓝"令牌贯穿全站：大字号流体排版、卡片默认描边透明 hover 显金、金色按钮扫光、章节金色竖条、Hero 篆刻印章；并区分前台浅色阴影与后台深色阴影。

**Q19：这个项目你最自豪的一点是什么？**
是"规范驱动"的工程化：从 Excel 转 SQL 的幂等导入、前后端对齐的 VO 设计，到 StateBlock/Pagination 等公共组件与设计令牌，整个项目是可维护、可扩展的，而不是一堆零散页面。

**Q20：如果继续做，下一步会加什么？**
三件事：一是接入真实地图 API（高德）替换占位地图；二是做用户评论与 UGC，让内容形成闭环；三是把 AI 从"行程生成"扩展到"实时导览"，结合定位做景区内语音讲解。
